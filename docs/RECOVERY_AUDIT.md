## Backend defects and security

- Auth project only references Swagger although source needs EF Core SQL Server, JWT,
  BCrypt and AutoMapper. `AuthResponse` does not define `Data` used by reset service.
  Committed configuration uses sample database/signing-key settings; actual secrets are not
  verified. Responses always HTTP 200, no DTO validation/throttling/reset delivery, raw reset
  token would be exposed and account existence disclosed.
- Course project has PackageReference outside ItemGroup, absent EF/JWT packages, missing
  context/User and auth types, copied registrations/mapper, misspelled `ValidAudience`.
  Controller route is `/api/course` while README promises plural `/api/courses`; arbitrary
  userId personalized route is anonymous. Pagination unbounded and sorting after slicing.
- Category project targets .NET 8 but controllers use `System.Web.Http`, context/repository
  use EF6, and Unity legacy DI does not run in the ASP.NET Core host. EF6 context calls EF Core
  `HasData`. PackageConfig XML has duplicate declaration. Useful business rules/DTOs should
  be retained during framework correction, not blindly replaced with the older branch.
- No actual authorization roles, outbox worker, webhook signature handling, migration apply,
  health/readiness, sensitive-log policy or integration tests exists.

## Database recovery

No current migrations or database files/services were found. The auth context maps Users;
course references a missing context; categories have a separate incompatible Course model.
Historical SQL inspected:

- `a089c73:web/APIs/Database.sql`: ALTER Users plus invalid sample BCrypt hashes (not migration).
- `e63b21b:web/APIs/Course Recommendations API /DAL/Database.sql`: Courses with string Category;
  UserCourseRecommendations unique `(UserID, CourseID)` and FK intent; ten sample courses.
- `66f99a8:web/APIs/Categories API/DAL/Database.sql`: Categories with unique Name, cached counts
  and trigger using Courses.Category. Current category model instead uses CategoryID FK.

These files remain recoverable from preserved Git history. Do not run partial legacy SQL against
an unknown database, seed fake users, or create three conflicting migration histories blindly.
Real database adoption requires an explicit unified schema strategy and relational validation.
